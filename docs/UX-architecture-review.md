# AShare 短线交易驾驶舱 · 前端 UX 架构审查与优化方案

> **角色**：用户体验架构师（ArchitectUX）  
> **范围**：前端流程、导航结构、页面布局、边缘场景处理  
> **目标**：消除流程断点、统一信息层级、降低认知负荷、建立可扩展的交互基线

---

## 1. 执行摘要

当前系统功能完整，已覆盖市场驾驶舱、推荐运行、候选解释、复盘、数据健康、回测、矩阵分析、控制中心等 11 个核心模块。但前端在**信息架构**和**流程编排**上存在明显断层：

- **核心功能被折叠在“测试窗口”抽屉中**，导致用户触达关键操作多一步点击；
- **DashboardPage 组件过于臃肿**（1400+ 行），同时承载 7 个业务视图，维护成本和渲染风险高；
- **页面间状态传递依赖 `sessionStorage` + 自定义事件**，跨页流程脆弱且无法深链接；
- **个股矩阵页采用独立内联样式**，与驾驶舱视觉体系不一致，破坏品牌感；
- **加载/空态/错误处理缺乏统一组件**，各页面自实现，体验参差不齐。

本报告给出**重新梳理后的四层导航模型**、**关键流程改造方案**、**页面布局建议**、**边缘场景设计规范**，以及**分阶段实施优先级**。

## 2. 当前用户操作路径与断点分析

### 2.1 当前导航结构（现状）

```
顶层导航
├── 矩阵推荐
│   ├── 个股矩阵 (stock-matrix)
│   └── 预设矩阵 (matrix)
├── 策略
│   ├── 回测 (backtest)
│   ├── 复盘结果 (history)
│   ├── 数据健康 (data)
│   └── 候选解释 (pool)
└── [配置窗口] 抽屉 → 测试窗口
    ├── 驾驶舱 (dashboard)
    ├── 推荐运行 (run)
    ├── 验收安全 (validation)
    └── 控制中心 (control)
```

### 2.2 核心断点与卡顿

| # | 断点 | 影响 | 证据 |
|---|------|------|------|
| **B1** | **“测试窗口”抽屉隐藏生产功能** | 驾驶舱、运行、验收、控制被用户感知为“测试/高级”，降低使用频率 | `NAV_GROUPS` 中 `test` 组包含 4 个核心模块，入口为抽屉按钮 |
| **B2** | **首页仅提供 2 个入口** | 新用户无法快速进入数据健康、运行、复盘等高频模块 | `home-entries` 只有“矩阵推荐”“策略” |
| **B3** | **DashboardPage 单文件承载 7 个视图** | 渲染压力大、逻辑耦合、代码冲突风险高 | `DashboardPage.tsx` 1400+ 行，条件分支多 |
| **B4** | **Run → Candidate → History 跨页依赖 sessionStorage** | 深链接失效、刷新后状态丢失、调试困难 | `CandidateWorkspace.openReplay` 使用 `sessionStorage.setItem('ashare:pendingReplayId', ...)` |
| **B5** | **个股矩阵视觉体系独立** | 用户感觉像进入另一个产品，降低信任感 | `StockMatrixPage.tsx` 大量使用内联 `style` 和硬编码色值 |
| **B6** | **自定义路由与浏览器历史不完全同步** | 前进/后退时部分内部状态不同步 | 路由依赖 `window.history.pushState` + 自定义事件 `ashare:navigate` |
| **B7** | **控制中心默认只展示“策略配置”** | 用户想配置任务或模型需再次点击二级 Tab | `ControlCenterPage` 默认 `activeControlSection = 'control-strategy'` |
| **B8** | **关键操作入口分散** | 运行推荐、刷新数据池、执行矩阵等动作位于不同页面，难以快速触达 | 没有全局“快捷操作栏”或“命令面板” |

### 2.3 用户任务流现状（示例：执行一次推荐并复盘）

```
[首页] → 点击“策略” → 进入回测/历史页（不一定对）
        → 或点击“测试窗口”抽屉 → 推荐运行 → 手动运行
        → 等待运行完成 → 点击“查看候选”
        → 候选解释页 → 点击“进入复盘”
        → 写入 sessionStorage → 跳转到复盘结果
        → 120ms 后触发 select-replay 事件加载详情
```

**问题**：
1. 入口需要经过抽屉，路径绕；
2. 运行完成后没有直接展示结果，而是靠用户跳转；
3. 复盘详情依赖异步事件，弱网或快速切换时可能丢失。

## 3. 重新设计的导航与交互流程

### 3.1 设计原则

1. **扁平化导航**：所有一级模块直接可见，不再隐藏在任何抽屉中；
2. **按任务场景分组**：按“洞察—执行—分析—配置”的心智模型重组；
3. **URL 即状态**：跨页跳转使用 URL 参数（`?run_id=...&recommendation_id=...`），支持深链接和刷新；
4. **一页一职责**：拆分 DashboardPage，每个 section 对应独立页面组件；
5. **全局可达的关键操作**：在顶部栏提供“运行推荐”“刷新数据池”等快捷入口；
6. **渐进式披露**：高级配置（模型路由、任务调度）收敛到配置中心，但不折叠。

### 3.2 优化后的导航模型

```
主导航（顶部栏 / 侧边栏）
├── 洞察
│   └── 驾驶舱 (dashboard) — 市场温度、龙头候选、风险雷达
├── 执行
│   ├── 推荐运行 (run) — 触发扫描、查看进度
│   ├── 候选解释 (pool) — 推荐卡片、个股解释
│   └── 复盘结果 (history) — outcome 标注、AI 复盘
├── 分析
│   ├── 预设矩阵 (matrix) — 多预设对比
│   ├── 个股矩阵 (stock-matrix) — 单票全 Skill 分析
│   └── 回测 (backtest) — 策略收益矩阵
└── 系统
    ├── 数据健康 (data) — 行情池、缺口、同步
    ├── 验收安全 (validation) — dry-run、门禁
    └── 控制中心 (control) — 预设、任务、模型路由
```

### 3.3 关键流程改造

#### 流程 A：执行一次推荐并复盘（优化后）

```
[任意页] → 顶部“运行推荐”快捷按钮
        → 选择预设 + 数据源 → 提交
        → 运行中：全局进度条 + 通知
        → 完成：自动推送通知，可一键“查看候选”
        → 候选解释页 → 卡片上“进入复盘”
        → 复盘结果页（URL 携带 ?recommendation_id=...）
        → 详情自动加载
```

#### 流程 B：盘前检查数据健康

```
[驾驶舱] → 顶部数据健康提示横幅
        → 一键“补齐数据池”
        → 数据同步页展示进度和结果
        → 返回驾驶舱继续运行
```

#### 流程 C：盘后批量分析

```
[分析 > 预设矩阵] → 查看最近批次
                 → 点击“执行矩阵”
                 → 运行中状态实时更新
                 → 完成：矩阵表格高亮最新批次
```

### 3.4 路由与状态规范

| 页面 | 推荐路径 | 关键参数 |
|------|---------|---------|
| 驾驶舱 | `/dashboard` | - |
| 推荐运行 | `/run?run_id=xxx` | `run_id` 用于恢复某次运行 |
| 候选解释 | `/pool?run_id=xxx` | `run_id` 限定展示该次候选 |
| 复盘结果 | `/history?recommendation_id=xxx` | `recommendation_id` 自动选中 |
| 个股矩阵 | `/stock-matrix?code=000001&trade_date=2026-07-03` | `code`, `trade_date` 支持分享链接 |
| 预设矩阵 | `/matrix` | - |
| 控制中心 | `/control?tab=strategy` | `tab` 控制二级分区 |

**建议**：如果重构成本允许，引入 `react-router-dom` 或 `wouter` 取代自定义路由，减少维护负担；若保持自定义路由，需确保所有内部跳转统一通过 `navigateToSection(path, params)` 工具函数，并同步 `window.history` 和 `URLSearchParams`。

## 4. 页面布局与信息层级优化

### 4.1 全局布局框架

```
┌─────────────────────────────────────────────┐
│  品牌 + 主导航 + 全局快捷操作 + 主题切换      │  ← 顶部栏 (64px)
├─────────────────────────────────────────────┤
│  子导航 / 面包屑                              │  ← 二级导航 (40px，可选)
├─────────────────────────────────────────────┤
│                                             │
│              主内容区                         │  ← 可滚动区域
│                                             │
├─────────────────────────────────────────────┤
│  全局任务进度 / 通知                            │  ← 底部或侧边浮层
└─────────────────────────────────────────────┘
```

### 4.2 顶部栏（关键操作入口）

当前顶部栏已有“刷新”“主题切换”和“配置窗口”。建议改为：

```
[品牌] [洞察] [执行] [分析] [系统]              [运行推荐 ▼] [刷新] [主题] [通知]
```

- **“运行推荐”下拉按钮**：快捷选择预设并执行，无需进入推荐运行页；
- **通知中心**：运行完成、数据同步完成、矩阵执行完成等事件聚合；
- **全局搜索**：未来可接入股票代码快速跳转（`cmd+k` / `ctrl+k`）。

### 4.3 驾驶舱布局（Dashboard）

现状为 3 列瀑布流，信息密度高但缺乏焦点。建议改为 **“先总览、再分区”** 的 F 型布局：

```
┌─────────────────────────────────────────────┐
│  数据健康横幅 + 市场温度摘要                  │  ← 第 1 行：系统状态
├─────────────────────────────────────────────┤
│  ┌──────────────┐  ┌──────────────────────┐ │
│  │  市场温度     │  │  龙头候选 / 推荐列表   │ │  ← 第 2 行：核心决策信息
│  │  风险雷达     │  │                      │ │
│  └──────────────┘  └──────────────────────┘ │
├─────────────────────────────────────────────┤
│  指标卡片区 · 运行状态 · 质量评分卡            │  ← 第 3 行：辅助数据
├─────────────────────────────────────────────┤
│  数据池健康 · 验证摘要 · 任务状态              │  ← 第 4 行：系统健康
└─────────────────────────────────────────────┘
```

**关键改进**：
- 将“龙头候选”置于视觉中心，符合短线交易核心决策场景；
- 市场温度、风险雷达作为左侧辅助；
- 运行状态用进度条或徽标展示，减少面板数量。

### 4.4 推荐运行页布局（Run）

现状信息较多但缺少主次。建议：

```
┌─────────────────────────────────────────────┐
│  预设选择 | 数据源 | [立即运行]              │  ← 操作区（sticky top）
├─────────────────────────────────────────────┤
│  运行时间线 + 当前阶段高亮                    │  ← 进度可视化
├─────────────────────────────────────────────┤
│  运行结果摘要 + 候选列表预览                  │  ← 产出区
└─────────────────────────────────────────────┘
```

**关键改进**：
- 操作区 sticky，长页面中仍可快速触发新运行；
- 运行时间线当前阶段高亮，已完成阶段显示对勾；
- 运行完成后直接展开“候选列表预览”，减少跳转。

### 4.5 候选解释页布局（Pool）

现状为卡片网格。建议改为 **列表 + 侧栏详情** 的 master-detail 模式：

```
┌─────────────────────────────────────────────┐
│  筛选器：买点 / 风险等级 / 分数区间            │  ← 顶部筛选
├────────────────────────┬──────────────────┤
│                        │                  │
│  候选列表               │   个股解释详情    │  ← 左列表、右详情
│  (排名/代码/分数/买点)   │   (原因/风险/共识)│
│                        │                  │
│                        │  [进入复盘]       │
│                        │                  │
└────────────────────────┴──────────────────┘
```

**关键改进**：
- 列表支持排序和筛选，提高扫读效率；
- 详情侧栏直接展示，无需跳转；
- “进入复盘”在详情内一键触达，URL 直接切换为 `/history?recommendation_id=xxx`。

### 4.6 控制中心布局（Control）

当前采用 Tab 切换三个大分区，合理。但建议在分区之间增加 **摘要卡片区**：

```
┌─────────────────────────────────────────────┐
│  预设数 | 可用模型 | 启用任务 | 本地池状态      │  ← 摘要卡片
├─────────────────────────────────────────────┤
│  [策略配置] [自动化] [模型接入]              │  ← Tab 切换
├─────────────────────────────────────────────┤
│  当前 Tab 内容                                │
└─────────────────────────────────────────────┘
```

## 5. 边缘场景优化方案

### 5.1 加载状态（Loading）

| 场景 | 现状 | 优化 |
|------|------|------|
| 整页初始化 | `DashboardLoadingState` 有标题 + 骨架 | 推广为全局 `PageSkeleton` 组件，所有页面复用 |
| 局部数据加载 | 部分区域无 loading | 在卡片内部使用 `CardSkeleton` 或 `InlineSpinner` |
| 长耗时任务（>3s） | Dashboard 有 `slowLoading` 提示 | 统一为 `SlowLoadingNotice`，说明预计等待原因 |
| 运行中进度 | 时间线高亮 + 状态徽标 | 增加全局任务进度条和完成通知 |

**建议组件规范**：

```tsx
<PageSkeleton title="正在加载驾驶舱数据" hint="正在连接后端并读取市场温度、候选解释和数据健康。" />
<CardSkeleton count={3} />
<InlineSpinner label="同步中…" />
<SlowLoadingNotice reason="后端正在整理行情、评估和数据池状态，当前请求还在继续。" />
```

### 5.2 空状态（Empty）

| 场景 | 现状 | 优化 |
|------|------|------|
| 无候选 | `candidate-empty` 有原因 + 操作 | 统一为 `EmptyState` 组件，带图标、原因、下一步 |
| 无运行 | 运行详情显示“暂无运行” | 提供“立即运行”引导 |
| 无复盘样本 | 显示可操作空态 | 提供“去运行”和“去候选”双入口 |
| 无数据池 | 数据健康提示 | 提供“补齐数据池”一键操作 |
| 无预设/任务/路由 | 控制中心显示“暂无…” | 提供“新建”引导按钮 |

**建议组件规范**：

```tsx
<EmptyState
  icon={<BarChart3 size={32} />}
  title="当前没有达标龙头候选"
  reason="缺少运行归因，不能直接视为市场无机会。"
  action={<Button onClick={goToRun}>去推荐运行</Button>}
/>
```

### 5.3 错误提示（Error）

| 场景 | 现状 | 优化 |
|------|------|------|
| 整页错误 | `error-state` 有重试 + 去控制中心 | 推广为 `ErrorPage` 组件，按错误类型给出建议 |
| 局部错误 | 部分区域有 `error-state` | 统一使用 `ErrorCard`，不影响其他区域操作 |
| 网络超时 | API 层有统一错误消息 | 增加“重试”和“检查后端状态”入口 |
| 部分失败 | 控制中心已处理 | 推广为 `PartialFailureBanner`，列出失败模块 |
| 权限错误 | 401 显示登录 | 优化为“访问密码”页，记住输入失败次数 |

**建议组件规范**：

```tsx
<ErrorPage
  title="驾驶舱加载失败"
  message="数据服务连接超时，请稍后重试。"
  actions={[
    { label: "重试", onClick: refresh },
    { label: "查看数据池", onClick: goToData },
  ]}
/>
<ErrorCard title="推荐详情加载失败" message={error} onRetry={retry} />
```

### 5.4 其他边缘场景

| 场景 | 处理方案 |
|------|---------|
| 运行中断 | 提供“断点继续”按钮；若不可恢复，提示失败原因并建议重跑 |
| 数据部分同步完成 | 使用 `warning` 色调横幅，展示成功/失败/剩余缺口数量 |
| 市场未开盘 | 驾驶舱显示“当前非交易时间”提示，并说明上次运行时间 |
| 多任务并发 | 全局任务队列浮层，展示运行中/排队中的任务 |
| 删除确认 | 当前“再点删除”机制合理，但建议改为二次确认弹窗，更符合直觉 |

## 8. 实施优先级建议

### Phase 1：导航重构（高优先级，1 周）
- 移除“测试窗口”抽屉，将 dashboard / run / validation / control 平铺到主导航；
- 重新设计首页入口，增加“运行推荐”“数据健康”“复盘”等快捷入口；
- 在顶部栏增加全局“运行推荐”快捷按钮和通知中心占位。

### Phase 2：页面拆分与路由改造（高优先级，1–2 周）
- 将 `DashboardPage` 拆分为 `DashboardPage` / `RunPage` / `PoolPage` / `DataPage` / `HistoryPage` / `BacktestPage` / `ValidationPage`；
- 用 URL 参数替代 `sessionStorage` 和自定义事件实现跨页状态；
- 若成本允许，引入 `react-router-dom` 替代自定义路由。

### Phase 3：统一边缘场景组件（中优先级，1 周）
- 提取 `PageSkeleton`、`CardSkeleton`、`EmptyState`、`ErrorPage`、`ErrorCard`、`SlowLoadingNotice`；
- 全站替换各页面自实现的 loading / empty / error UI；
- 统一错误提示文案和色调。

### Phase 4：布局优化（中优先级，1–2 周）
- 驾驶舱改为 F 型布局，突出龙头候选；
- 候选解释页改为 master-detail；
- 运行页操作区 sticky，增加产出预览；
- 个股矩阵页接入全局 token 和组件库。

### Phase 5：全局体验增强（低优先级，后续迭代）
- 全局搜索 / 命令面板（`cmd+k`）；
- 运行/同步任务全局进度条；
- 通知中心聚合所有异步事件；
