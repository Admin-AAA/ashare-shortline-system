# 教训表可靠性核验报告

核验日期：2026-08-15
核验对象：[`LESSONS.md`](./LESSONS.md) 的 L-001～L-057
核验原则：当前代码/测试/数据库优先；历史报告只作为证据线索，不把旧数字自动当成当前事实。

## 结论先行

57 条教训不能全部视为同等可靠：

| 分级 | 数量 | 含义 |
| --- | ---: | --- |
| A 当前可采信 | 30 | 当前代码、测试或数据库现状能直接支持规则；其中收益数字仍需看具体 scope。 |
| B 历史证据支持 | 13 | 原始来源存在且方法/原则仍合理，但当前没有同口径独立重放，不能直接拿旧数字做发布依据。 |
| C 部分失效或实现缺口 | 4 | 原则有价值，但当前发布流程或实现与条目不一致。 |
| D 当前快照反驳原始表述 | 2 | 历史事故可能真实发生过，但当前数据库不再呈现条目所写的状态。 |
| E 当前无法复现/原证据不合格 | 8 | 缺少同口径可重放结果，或已有产物暴露出样本/判定缺陷；暂禁用其经验数字。 |

这不是给教训永久盖章。`A` 主要表示“规则可用”，不表示策略收益必然为正；`B/E` 的收益结论在新样本出现前不得升级为生产事实。

## 高风险发现

1. 当前没有可结算的正式前瞻样本：7 个 `live_forward` run 均 completed 但推荐数为 0，`live_forward` outcome 数为 0。当前 `self_check` 也报告没有 settled LIVE formal，因此 L-001/L-002/L-012～L-018 中涉及当前 LIVE 表现的数字暂不能重验。
2. `output/si_score_line_grid_path_a_v2.json` 不能作为 L-027 的证据：其中 challenger 样本仅 2、3、11、20 笔，却被标成 `PRODUCTION`，bootstrap 还出现 `insufficient_common` 或全零区间。这是典型的“模型有输出，但证据不合格”。操作手册已经把旧 score-line grid 脚本标为 archived。
3. `output/stop_loss_width_grid_20260731.json` 是 20cm formal、`n=33`、champion `-5.5%` 的另一 scope；它不能证明 L-026 所写的 Path-A 全历史 `n=3611`、`-4.5%` 结论。`output/sequential_champion_replay.json` 当前为 `n=0` 且无 decision，也不能作为当前 champion 的重放证据。
4. 融资余额当前快照没有复现 L-055/L-056 的单位切换：`margin_detail` 262,866 行中，07-16 前后均值约为 6，两个区间 `rzye>1e8` 均为 0%。因此原始“07-16 起从元变亿元”的具体数字只能保留为历史事件，不能当作当前数据库事实。
5. L-014 的因果原则仍合理，但当前 [`capital_flow_factor_evidence.py`](../../backend/app/services/capital_flow_factor_evidence.py) 仍使用 `cf.trade_date = r.trade_date` 的 T-day join，说明“教训成立”和“系统已经落实”是两件事；该条应列为实现缺口，不能标成 fully encoded。
6. L-009/L-010/L-015 的“样本量、窗口、Canary 不构成发布门槛”与当前状态机不一致：当前代码存在 `MIN_FORWARD_SAMPLES=20`、`provisional n<50`、deployment receipt 和 Canary coverage/productive-day gate。当前 `challenger_decision` 仍是指标判定器，但不是整个发布流程的唯一闸门。
7. 当前 Path-A champion-only 重放确实能跨三个独立窗口运行，但它不是旧网格的同口径复现：2025-H1 `n=1689 / avg +0.1247% / PF 1.0609`，2025-H2 `n=3228 / avg +0.9792% / PF 1.6011`，2026-H1 `n=3050 / avg +0.0047% / PF 1.0021`。当前脚本总计 7,967 笔，配置为 trailing `0.50`；旧条目多使用 `n=3611`、trailing `0.30` 或另一套 champion。因此它支持“当前 Path-A 有跨窗诊断能力”，不能反向证明 L-020/L-026/L-027/L-029/L-031/L-034～L-036 的旧网格数字。

## 核验方法与数据范围

- 使用项目虚拟环境 `backend/.venv`；未写入生产数据库。
- 只读数据库画像：`daily_kbars` 2,185,227 行，覆盖 2021-05-26～2026-08-14，`(code, trade_date)` 重复键为 0；`recommendations` 206 行但只有 81 个唯一 `(trade_date, code)`，因此报告和回测必须去重。

- `self_check.py` 当前结果：G0 PASS；G1 无 settled LIVE formal；G2 有 1 个 disconnected running；G3 性能样本不足；近期 LLM review 成功率为 0%。

## 后续使用规范

1. 研究和发布只允许把 A 类规则作为当前约束；B 类必须显式标注“历史证据”；C/D/E 类不得直接驱动模型改参或生产发布。
2. 收到新一批 LIVE formal outcome 后，优先重验 B/C 类；恢复 L-014 的 strictly-prior-day join 后再重新评估相关因子结论。
3. 要恢复 E 类，必须保存：输入快照、代码 commit、唯一 scope、去重规则、窗口、参数、逐笔结果、配对 CI 和最终判定；只保存一段总结文字不算可复现证据。
4. 本报告是 `LESSONS.md` 的可靠性审计，不另建第二份教训库；新核验结果追加到本报告或对应证据档案，并在教训条目中回链。
