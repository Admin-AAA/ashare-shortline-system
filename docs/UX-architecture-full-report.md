## 1. 执行摘要

当前系统功能完整，覆盖市场驾驶舱、推荐运行、候选解释、复盘、数据健康、回测、矩阵分析、控制中心等 11 个核心模块。但前端在**信息架构**和**流程编排**上存在明显断层：

1. **核心功能被折叠在"测试窗口"抽屉中**——驾驶舱、运行、验收、控制被用户感知为"测试/高级"，降低使用频率；
2. **DashboardPage 单文件承载 7 个业务视图**（1400+ 行），维护成本和渲染风险高；
3. **跨页流程依赖 `sessionStorage` + 自定义事件**，刷新即丢状态，无法深链接；
4. **个股矩阵页视觉体系独立**（内联样式 + 硬编码色值），与驾驶舱不像一个产品；
5. **加载/空态/错误处理各做各的**，体验参差不齐。

**核心优化方向**（v2.1 经设计审查后确定）：

- 取消"测试窗口"抽屉，按**使用频率**线性排列导航（驾驶舱 → 候选池 → 复盘 → 矩阵 → 配置）；
- 驾驶舱精简：从 3 列 9 面板压缩为 2 列 3 面板 + 1 状态条，只保留 30 秒决策所需的核心信息；
- 把验收安全、数据健康、模型路由等能力**内化到系统后台**，用户无需主动感知；
- 推荐运行前置到**驾驶舱主 CTA**，形成「驾驶舱 → 运行 → 候选池 → 复盘」连贯链路；
- 历史复盘重塑为**"成功率档案"**，支持「驾驶舱成功率快报 → 下钻归因」回访链路；
- 候选解释页改为**可展开行**模式（替代原方案 master-detail），支持多票并排对比；
- 用 URL 参数替代 `sessionStorage` 实现跨页状态，支持深链接和刷新保持。

## 2. 现状与断点分析

### 2.1 当前导航结构

```
顶层导航
├── 矩阵推荐
│   ├── 个股矩阵 (stock-matrix)
│   └── 预设矩阵 (matrix)
├── 策略
│   ├── 回测 (backtest)
│   ├── 复盘结果 (history)
│   ├── 数据健康 (data)
│   └── 候选解释 (pool)
└── [配置窗口] 抽屉 → 测试窗口
    ├── 驾驶舱 (dashboard)
    ├── 推荐运行 (run)
    ├── 验收安全 (validation)
    └── 控制中心 (control)
```

### 2.2 已识别断点（8 处）

| # | 断点 | 影响 | 证据 |
|---|------|------|------|
| **B1** | "测试窗口"抽屉隐藏生产功能 | 核心操作多一步点击，用户感知为"测试" | `NAV_GROUPS` 中 `test` 组含 4 个核心模块 |
| **B2** | 首页仅提供 2 个入口 | 新用户无法快速进入高频模块 | `home-entries` 只有"矩阵推荐""策略" |
| **B3** | DashboardPage 单文件 1400+ 行 | 渲染压力、逻辑耦合、冲突风险高 | `DashboardPage.tsx` 承载 7 个视图 |
| **B4** | 跨页依赖 `sessionStorage` | 深链接失效、刷新丢状态 | `CandidateWorkspace.openReplay` 写 sessionStorage |
| **B5** | 个股矩阵视觉体系独立 | 用户感觉像另一个产品 | `StockMatrixPage.tsx` 大量内联 style |
| **B6** | 自定义路由与浏览器历史不同步 | 前进/后退时内部状态不一致 | 依赖 `window.history.pushState` + 自定义事件 |
| **B7** | 控制中心默认只展示"策略配置" | 用户需再次点击二级 Tab | `activeControlSection = 'control-strategy'` |
| **B8** | 关键操作入口分散 | 运行、刷新数据池、执行矩阵位于不同页面 | 无全局快捷操作栏 |

### 2.3 典型用户任务流（现状 vs 优化后）

**现状：执行推荐并复盘**

```
[首页] → 点击"策略" → 进入回测/历史页（不一定对）
       → 或点击"测试窗口"抽屉 → 推荐运行 → 手动运行
       → 等待运行完成 → 点击"查看候选"
       → 候选解释页 → 点击"进入复盘"
       → 写入 sessionStorage → 跳转到复盘结果
       → 120ms 后触发 select-replay 事件加载详情
```

**问题**：入口需经抽屉（路径绕）；运行完成无直接结果展示；复盘依赖异步事件，弱网可能丢失。

**优化后：**

```
[驾驶舱] → 点击"运行今日推荐"主 CTA → 确认面板（选择预设/查看预计耗时）
        → 运行中（状态条显示进度，可切换到其他页面）
        → 运行完成（通知推送 + 状态条更新）
        → 点击候选卡片或状态条 → 候选池（/pool?run_id=xxx）
        → 展开候选行查看解释 → 点击"进入复盘"
        → 复盘页（/history?recommendation_id=xxx，URL 深链接）
```

**改善**：入口直达驾驶舱主按钮；运行完成后自动通知；跨页状态全部通过 URL 参数，刷新不丢、可分享。

## 3. 测试窗口功能解构

> 本节回答：「测试窗口里的东西真的是高频吗？哪些可以内化？」

### 3.1 功能重新分类

当前"测试窗口"抽屉中的 4 个模块，按"用户是否需要主动感知"重新分类：

| 模块 | 当前入口 | 用户感知 | 真实使用频率 | 分类结论 |
|------|----------|----------|--------------|----------|
| 驾驶舱 (dashboard) | 测试窗口抽屉 | 像"测试工具" | **最高频** | ❌ 不应在测试窗口，应提升为首页 |
| 推荐运行 (run) | 测试窗口抽屉 | 像"调试触发" | **高频**（手动触发时） | ❌ 不应在测试窗口，应前置到驾驶舱主 CTA |
| 验收安全 (validation) | 测试窗口抽屉 | 像"门禁检查" | 中低频 | ✅ **应内化**，后台自动执行，异常时告警 |
| 控制中心 (control) | 测试窗口抽屉 | 像"系统配置" | 低频 | ⚠️ 不应在测试窗口，但独立为配置区合理 |

**结论**："测试窗口"的命名本身就在告诉用户"这些是调试功能"，但除了控制中心的配置属性外，其余三项都是生产链路的核心环节。把生产链路放在"测试窗口"里，是**导航语义与功能重要性不匹配**。

### 3.2 应内化的能力清单

#### 验收安全（Validation）→ 融入运行状态与告警

- 在**驾驶舱顶部状态条**显示当前系统健康与门禁状态；
- **推荐运行前**自动做一次 dry-run 检查，异常时直接阻断并提示；
- 运行中/运行后，将验证告警作为运行状态的一部分展示；
- 仅在出现高风险告警时，通过顶部 banner 或运行详情页展开明细；
- "验收安全"页保留为详细诊断页，日常不需要用户进入。

#### 数据健康（Data Health）→ 运行前自动检查与自动补齐

- 驾驶舱显示"数据就绪"状态标签；
- 用户点击"运行推荐"时，后端先自动检查数据 readiness：
  - **健康** → 直接运行；
  - **轻度缺口** → 后台自动补齐，提示"正在补齐数据"；
  - **严重缺口** → 阻断运行，给出明确原因和手动修复入口；
- "数据健康"页保留为详细诊断页，迁至配置区。

#### 模型路由（Model Route）→ 配置后无感知

- **配置期**：在控制中心完成路由新增、测试、排序；
- **运行期**：系统按优先级自动切换路由，用户无感知；
- **异常期**：仅当所有路由不可用时，才向用户展示告警，并给出"去控制中心检查"入口。

### 3.3 重复功能识别与合并

| 功能 | 重复出现位置 | 问题 | 合并方案 |
|------|--------------|------|----------|
| 手动运行推荐 | 控制中心"立即执行"、Dashboard 运行面板、RunWorkspace | 同一动作不同形态 | 统一入口在**驾驶舱一键运行**；控制中心"立即执行"仅用于自动任务调试 |
| 候选解释 | Dashboard `DragonCandidatesPanel`、`pool` 工作区 | 同一份数据展示两处 | 首页保留"今日 top 3–5 候选"快照；完整列表放到"推荐结果 → 候选解释" |
| 进入复盘 | 候选解释卡、复盘页空态、运行完成提示 | 多处文案不统一 | 统一按钮文案为「查看复盘」，URL 携带 `?recommendation_id=xxx` |
| 刷新状态 | 几乎每个页面都有"刷新状态"按钮 | 操作分散 | 提供全局刷新/自动轮询，页面级刷新仅在详情页保留 |

## 4. 推荐双链路重构

> 本节回答：「用户现在要执行推荐应该怎么走」「下次回来想看之前的成功率应该怎么玩」

### 4.1 链路一：执行推荐（触发 → 运行 → 产出 → 复盘）

```
驾驶舱（首页）
 │ 查看今日市场状态、数据 readiness、成功率快报
 │ 主按钮：运行今日推荐（若今日未运行）
 │          或 查看今日候选（若已运行完成）
 ↓
运行详情页（/run?run_id=xxx）
 │ 显示阶段时间线、进度、心跳、产出摘要
 │ 系统已自动完成数据健康与验收检查（用户无需主动操作）
 ↓
候选解释页（/pool?run_id=xxx）
 │ 展示本次运行产出的候选列表与解释卡
 │ 每张卡可直接进入复盘（URL 跳转，不复用 sessionStorage）
 ↓
复盘详情页（/history?recommendation_id=xxx）
 │ 展示单个票的 outcome、收益、误判归因
 │ 或查看整次运行的成功率与归因分析
```

**关键变化**：
1. 运行入口是**驾驶舱主 CTA**，不再藏在"测试窗口"；
2. 数据健康、验收安全在运行前**自动完成**，不需要用户主动进入；
3. 运行完成**自动引导**到候选解释，无需手动跳转；
4. 候选解释 ↔ 复盘之间用 URL 参数深链接，刷新不丢失。

### 4.2 链路二：回访成功率（概览 → 下钻 → 归因）

```
驾驶舱（首页）
 │ 成功率快报：今日成功率 / 近 5 日成功率 / 累计净收益 / 主要误判原因
 │ 点击任一指标
 ↓
历史复盘页（/history，按时间组织）
 │ 按日期 / run 分组展示推荐列表
 │ 每行显示：运行日、标的数、成功率、平均收益、误判率
 │ 筛选器：只看误判 / 按原因筛选 / 按市场环境筛选
 ↓
单次 run 复盘（/history?run_id=xxx）
 │ 查看该次运行的所有推荐与成功率
 ↓
单个票复盘（/history?recommendation_id=xxx）
 │ 查看该票的触发条件、收益、outcome、归因
```

**关键变化**：
1. 首页**直接展示**"成功率快报"，让用户一眼看到策略表现；
2. 历史复盘不再是"当前推荐的详情页"，而是**按时间组织的成功率档案**；
3. 从成功率快报 → 历史复盘 → 单次归因，形成**可下钻链路**；
4. 支持导出筛选后的复盘样本，用于人工二次分析。

## 5. 优化后导航模型

### 5.1 设计原则

1. **频率驱动导航**：按用户操作频率从左到右排列，核心流（驾驶舱 → 候选池 → 复盘）相邻，无需跨组跳转；
2. **URL 即状态**：跨页跳转使用 URL 参数，支持深链接和刷新；
3. **一页一职责**：拆分 DashboardPage，每个 section 对应独立页面组件；
4. **全局可达的关键操作**：在顶部栏提供"运行推荐"等快捷入口；
5. **渐进式披露**：高级配置收敛到配置中心，从主导航后置。

> **设计原则变更说明**（v2.1）：原方案的四层导航"洞察/执行/分析/系统"按功能类别分组，导致核心操作流（驾驶舱→候选→复盘）跨越多个导航组。短线交易者不是来"浏览功能"的，是来完成一个连贯决策链路的。改为频率驱动的线性导航。

### 5.2 优化后完整导航结构

```
主导航（顶部栏，按使用频率从左到右排列）
├── 🏠 驾驶舱 (dashboard) — 首页，市场温度、龙头候选、运行状态、成功率快报
├── 🎯 候选池 (pool) — 候选卡片、个股解释、LLM 可信度
├── 📊 复盘 (history) — 成功率档案、outcome 归因、下钻分析
├── 📈 矩阵 (matrix) — 个股矩阵 + 预设矩阵（合并）
└── ⚙️ 配置 (control) — 策略配置、自动化任务、模型路由、回测、数据健康（详细诊断）
```

> **注 1**："推荐运行"不再作为独立导航入口。运行入口是驾驶舱的主 CTA（"运行今日推荐"按钮），运行详情通过 `/run?run_id=xxx` 访问。
> **注 2**："验收安全"不再作为独立导航入口，其信息融入驾驶舱状态条与运行详情页。
> **注 3**："回测"和"数据健康"迁入配置区，保留为详细诊断页，日常不需要用户进入。
> **注 4**：控制中心默认 Tab 从"策略配置"改为记录用户上次选择的 Tab，避免每次进入都要重新点击。

### 5.3 路由与状态规范

| 页面 | 推荐路径 | 关键参数 | 深链接支持 |
|------|----------|----------|------------|
| 驾驶舱 | `/dashboard` | - | ✅ |
| 推荐运行 | `/run?run_id=xxx` | `run_id` 恢复某次运行详情 | ✅ |
| 候选池 | `/pool?run_id=xxx` | `run_id` 限定展示该次候选 | ✅ |
| 复盘结果 | `/history?recommendation_id=xxx` | `recommendation_id` 自动选中并展开 | ✅ |
| 个股矩阵 | `/stock-matrix?code=000001&trade_date=2026-07-03` | `code`, `trade_date` | ✅ 支持分享 |
| 配置中心 | `/control?tab=strategy` | `tab` 控制二级分区；记住上次选择 | ✅ |

> **注**：`/run` 路径保留用于运行详情回访，但不作为主导航入口。日常触发运行通过驾驶舱主 CTA。运行中/完成后，点击状态条可跳转到 `/run?run_id=xxx`。

## 6. 页面布局规范

> 本节给出每个关键页面的布局建议，**附 SVG 设计图**，开发 Agent 应参照 SVG 实现。

### 6.1 全局布局框架

所有页面共享同一套布局骨架：

```
┌──────────────────────────────────────────────────────────┐
│  品牌 + 主导航（驾驶舱/候选池/复盘/矩阵/配置）+ 主题切换    │  ← 顶部栏 (64px)
│  [▶ 运行推荐 ▼] [🔔 通知] [🔄 刷新]                       │  ← 快捷操作区
├──────────────────────────────────────────────────────────┤
│  驾驶舱专属：36px 状态条（数据就绪 · 运行状态 · 胜率）      │  ← 二级信息条（仅驾驶舱）
├──────────────────────────────────────────────────────────┤
│                                                          │
│                    主内容区                                │  ← 可滚动区域
│                                                          │
├──────────────────────────────────────────────────────────┤
│  全局任务进度 / 通知托盘                                    │  ← 底部或侧边浮层
└──────────────────────────────────────────────────────────┘
```

**顶部栏快捷操作区**（所有页面共享）：

```
[品牌] [驾驶舱] [候选池] [复盘] [矩阵] [配置]      [▶ 运行推荐 ▼] [🔔] [🔄] [🌙]
```

- "运行推荐"下拉按钮：快捷选择预设并执行，无需离开当前页面。运行中的任务在按钮上显示 mini 进度环；
- 通知中心（🔔）：运行完成、数据同步完成、任务异常等事件聚合。运行完成通知包含直达候选池的链接；
- 全局刷新按钮（🔄）：触发当前页面数据重载。

### 6.2 驾驶舱页面（/dashboard）布局

**设计图**：`docs/ux-architecture-layout-dashboard.svg`

**设计原则**：驾驶舱的职责不是"展示所有数据"，而是在 **30 秒内回答三个问题**：① 今天能不能做？② 跑出结果了吗？③ 有哪些候选？其余信息（质量评分、过滤分析、验收通过率、数据健康详情）属于事后分析链路，不应抢占交易决策的注意力。

**精简决策**：当前驾驶舱 3 列 9 面板（市场温度、质量评分卡、过滤有效性、风险雷达、指标总览、运行状态、龙头候选、数据健康、验收摘要）。精简后保留 2 列 3 面板 + 1 状态条：

| 面板 | 处理方式 | 理由 |
|------|----------|------|
| 🐉 龙头候选 | **保留** | 驾驶舱存在的理由——直接回答"做哪个" |
| 🟡 市场温度 | **保留**（合并风险雷达） | 回答"能不能做"；风险信号作为温度面板内的子指标行 |
| ▶️ 运行状态 | **保留** | 今天跑没跑推荐？什么时候跑的？产出多少？ |
| 🎯 风险雷达 | → 合并进市场温度 | 与市场温度功能重叠，合并为温度面板内的信号指标行 |
| 📊 指标总览 | → 候选面板顶部 KPI 行 | 候选数/平均分/通过率 3 个数字，不需要独立面板 |
| 🏥 数据健康 | → 顶部状态条 | 用户只需知道能不能跑：🟢 就绪 / 🟡 缺口 / 🔴 暂停 |
| 📊 质量评分卡 | → 移到回测页 | 策略开发调试工具，交易日决策无需关注 |
| 🔍 过滤有效性 | → 移到回测页 | 同上——哪个过滤拦截了多少候选，是校准阶段的事 |
| ✅ 验收摘要 | → 移到运行结果页 | 门禁通过率是系统内部指标，跑完再看 |

**精简后布局**（2 列 × 2 区 + 1 状态条）：

```
┌──────────────────────────────────────────────────────────┐
│ 🟢 数据就绪 · 今日已运行(14:32) · 候选 8 只 · 近5日胜率 75% │  ← 36px 状态条（sticky，始终可见）
├──────────────────────────┬───────────────────────────────┤
│                          │                               │
│  🟡 市场温度              │  🐉 龙头候选                   │
│  温度计 + 阶段标签        │  ┌──────┐ ┌──────┐ ┌──────┐  │
│  ───────────────         │  │ 票 1 │ │ 票 2 │ │ 票 3 │  │
│  风险信号（合并雷达）      │  └──────┘ └──────┘ └──────┘  │
│  · 涨跌比  · 量能变化     │  ┌──────┐ ┌──────┐          │
│  · 连板高度  · 炸板率     │  │ 票 4 │ │ 票 5 │          │
│                          │  └──────┘ └──────┘          │
│  ▶️ 运行状态               │                               │
│  今日运行：14:32 完成      │  候选 8  ·  均分 72  ·  通过 80% │  ← KPI 行
│  耗时 48s · 产出 8 只     │                               │
│  [▶ 重新运行] [查看历史]   │  [查看全部候选 →]             │
│                          │                               │
│                          │  🟡 未运行态：                 │
│                          │  [▶ 运行今日推荐] 主 CTA       │
│                          │  下方 mini 文案：预设/预计耗时 │
│                          │                               │
└──────────────────────────┴───────────────────────────────┘
```

**两种运行状态下的 CTA 交互规范**：

- **未运行态**（今日尚未运行推荐）：右列顶部显示 `[▶ 运行今日推荐]` 主按钮 → 点击后弹出微型确认面板（非 modal），展示：预设名称 + 预计耗时 + "上次运行于 X 小时前" → 二次点击「确认运行」
- **已运行态**（推荐已完成）：右列顶部显示候选卡片，"运行今日推荐"按钮降级为运行状态面板内的 `[▶ 重新运行]` 次要按钮
- **运行中态**：状态条显示进度（"正在运行… 阶段 2/4"），右列顶部显示骨架屏

**关键设计决策**：
- 龙头候选占右侧 60% 宽度，作为视觉重心；
- 市场温度（合并风险雷达）占左侧 40% 宽度，提供环境判断；
- 顶部 36px 状态条 sticky 滚动，用 🟢🟡🔴 颜色编码数据就绪状态，异常时变色告警；
- 成功率快报集成在顶部状态条中（"近 5 日胜率 75%"），hover 展开 mini 趋势图，点击下钻到历史复盘页；
- 运行状态面板紧凑显示：运行时间 + 耗时 + 产出数量 + 结果摘要（一行），不展开详情。

### 6.4 候选解释页（/pool）布局

├──────────────────────────────────────────────────────────┤
│  候选列表（表格/卡片行）                                     │
│  ┌──────────────────────────────────────────────────┐   │
│  │ #1  000001 平安银行  72 分  🟢 回调买点  [展开 ▼]  │   │
│  ├──────────────────────────────────────────────────┤   │
│  │ ┌─────────────────────┬─────────────────────────┐│   │
│  │ │ 买点原因 / 风险提示   │  LLM 可信度：🟡 中等      ││   │  ← 展开行（可同时展开多行）
│  │ │ · 均线支撑叠加重组    │  · 确定信号：2 项         ││   │
│  │ │ · 风险：高位换手不足  │  · 不确定信号：1 项       ││   │
│  │ │                      │  · 基于历史验证：3/5 项   ││   │
│  │ │ [📊 进入复盘]         │  [📋 复制解释]           ││   │
│  │ └─────────────────────┴─────────────────────────┘│   │
│  └──────────────────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────────────┐   │
│  │ #2  600519 贵州茅台  68 分  🟡 突破买点  [展开 ▼]  │   │
│  └──────────────────────────────────────────────────┘   │
│  ...                                                    │
└──────────────────────────────────────────────────────────┘
```

**关键设计决策**：
- 摒弃原方案的 master-detail（左列表右详情），改为**可展开行**模式——短线交易者需要同时对比 2-3 只候选的买点和风险，master-detail 一次只能看一个，无法并排对比；
- 点击行展开详情面板（手风琴模式），支持同时展开多行进行并排对比；
- 每张展开卡包含：买点原因、风险提示、LLM 解释可信度指示器（用 🟢🟡🔴 颜色编码确定性等级，而非裸分数）；
- "进入复盘"在展开行内一键触达，URL 切换为 `/history?recommendation_id=xxx`；
- LLM 可信度指示器：展示"确定信号数 / 不确定信号数 / 历史验证率"三项，帮助用户判断解释质量。

## 7. 边缘场景规范

### 7.1 加载状态（Loading）

| 场景 | 现状 | 优化方案 | 统一组件 |
|------|------|----------|----------|
| 整页初始化 | `DashboardLoadingState` 有标题+骨架 | 推广为全局 `PageSkeleton` | `<PageSkeleton title="正在加载驾驶舱数据" hint="..." />` |
| 局部数据加载 | 部分区域无 loading | 卡片内部使用 `CardSkeleton` | `<CardSkeleton count={3} />` |
| 长耗时任务（>3s） | Dashboard 有 `slowLoading` 提示 | 统一为 `SlowLoadingNotice` | `<SlowLoadingNotice reason="..." />` |
| 运行中进度 | 时间线高亮 + 状态徽标 | 增加全局任务进度条 | `<GlobalProgress taskName="推荐运行" progress={60} />` |

**`PageSkeleton` 组件规范**：

```tsx
interface PageSkeletonProps {
  title: string;          // 页面标题（显示在骨架顶部）
  hint?: string;          // 可选：说明当前在加载什么（如"正在连接后端并读取市场温度..."）
  showSidebar?: boolean;  // 是否显示侧栏骨架（默认 false）
  rowCount?: number;      // 内容区骨架行数（默认 3）
}
```

---

### 7.2 空状态（Empty）

| 场景 | 优化方案 | 统一组件 |
|------|----------|----------|
| 无候选 | 显示原因 + 提供"去运行"操作 | `<EmptyState icon={...} title="当前没有达标龙头候选" reason="..." action={<Button>去推荐运行</Button>} />` |
| 无运行记录 | 提供"立即运行"引导 | 同上，action 指向 `/run` |
| 无复盘样本 | 提供"去运行"和"去候选"双入口 | `actions` 数组支持多个操作 |
| 无数据池 | 显示"补齐数据池"一键操作 | action 触发后端自动补齐 |
| 无预设/任务/路由 | 提供"新建"引导按钮 | action 打开对应新建对话框 |

**`EmptyState` 组件规范**：

```tsx
interface EmptyStateProps {
  icon: ReactNode;       // 场景图标（用 lucide-react 图标）
  title: string;          // 空状态标题（如"当前没有达标龙头候选"）
  reason?: string;        // 可选：说明为什么为空（帮助理解，非责备）
  action?: ReactNode;     // 主要操作按钮
  secondaryAction?: ReactNode;  // 可选：次要操作
}
```

---

### 7.3 错误提示（Error）

| 场景 | 优化方案 | 统一组件 |
|------|----------|----------|
| 整页错误 | 推广为 `ErrorPage`，按错误类型给出建议 | `<ErrorPage title="驾驶舱加载失败" message="..." actions={[...]} />` |
| 局部错误 | 使用 `ErrorCard`，不影响其他区域 | `<ErrorCard title="推荐详情加载失败" message={error} onRetry={retry} />` |
| 网络超时 | 增加"重试"和"检查后端状态"入口 | ErrorPage actions 包含重试 + 诊断 |
| 部分失败 | 推广为 `PartialFailureBanner` | `<PartialFailureBanner failures={[...]} />` |
| 权限错误 | 优化为"访问密码"页 | 独立 `PasswordPage` 组件 |

**`ErrorPage` 组件规范**：

```tsx
interface ErrorPageProps {
  title: string;          // 错误标题
  message: string;         // 错误详情
  errorCode?: string;      // 可选：错误码（用于技术支持）
  actions: {              // 操作按钮列表
    label: string;
    onClick: () => void;
  }[];
}
```

### 7.4 其他边缘场景

| 场景 | 处理方案 |
|------|----------|
| 运行中断 | 提供"断点继续"按钮；若不可恢复，提示失败原因并建议重跑 |
| 数据部分同步完成 | 使用 `warning` 色调横幅，展示成功/失败/剩余缺口数量 |
| 市场未开盘 | 驾驶舱显示"当前非交易时间"提示，并说明上次运行时间 |
| 多任务并发 | 全局任务队列浮层，展示运行中/排队中的任务 |
| 删除确认 | 改为二次确认弹窗（当前"再点删除"机制不够直观） |
| 运行中用户离开页面 | 顶部栏快捷操作区的"运行推荐"按钮显示 mini 进度环，点击回到运行详情；运行完成/失败通过通知中心推送，不打断当前操作 |
| 候选池多票对比 | 可展开行模式支持同时展开 2-3 行，并排对比买点和风险；超过 3 行展开时提示"已展开 N 行，可能超出可视范围" |
| LLM 解释可信度 | 每张候选展开卡展示可信度指示器：确定信号数 🟢 / 不确定信号数 🟡 / 历史验证率（百分比+进度条），帮助用户判断解释质量，而非只看分数 |
| 复盘→策略调整闭环 | 归因总结区域增加「优化建议」区块，基于误判模式自动生成策略调整提示（如"近 5 次误判均在弱势市场，建议降低 score 阈值"），并提供「去配置调整」一键入口 |

## 8. 实施路线图

### 阶段划分与优先级

| 阶段 | 内容 | 优先级 | 预估工作量 |
|------|------|--------|------------|
| **P0** | 取消"测试窗口"抽屉，导航改为频率驱动线性排列（驾驶舱/候选池/复盘/矩阵/配置） | 最高 | 3–5 天 |
| **P0** | 驾驶舱精简：9 面板 → 3 面板 + 1 状态条；"一键运行"CTA 含确认机制 | 最高 | 3–5 天 |
| **P0** | 用 URL 参数替换 `sessionStorage` 的跨页跳转（仅有 1 个 key，改动面小） | 最高 | 1–2 天 |
| **P1** | 拆分 DashboardPage：独立出 HomePage、RunDetailPage、PoolPage、HistoryPage 等 | 高 | 1–2 周 |
| **P1** | 统一边缘场景组件（PageSkeleton / EmptyState / ErrorPage / ErrorCard），对接现有 themes.css Token | 高 | 1 周 |
| **P1** | 候选解释页改为可展开行模式（替代原 master-detail），含 LLM 可信度指示器 | 高 | 1 周 |
| **P2** | 将验收安全/数据健康信息融入驾驶舱状态条与运行详情（内化） | 中 | 3–5 天 |
| **P2** | 重构历史复盘页为"成功率档案"布局，增加复盘→策略优化建议区块 | 中 | 1 周 |
| **P2** | 驾驶舱成功率快报集成至顶部状态条（hover 展开趋势，点击下钻） | 中 | 3–5 天 |
| **P3** | 数据健康与模型路由的后台化细节优化 | 中 | 1 周 |
| **P3** | 个股矩阵页接入全局 Token 和组件库（131 处内联样式需要清理） | 中 | 1 周 |
| **P3** | 全局通知中心 + 运行中进度指示器 | 低 | 1 周 |

## 10. 附：设计决策记录（ADR）

### ADR-004：驾驶舱精简——只保留 30 秒决策信息

**状态**：已决定  
**背景**：当前驾驶舱 3 列 9 面板（市场温度、质量评分卡、过滤有效性、风险雷达、指标总览、运行状态、龙头候选、数据健康、验收摘要）。其中质量评分卡和过滤有效性是策略调试工具，数据健康详情和验收摘要是系统运维指标，均不属于交易决策的核心信息。  
**决定**：精简为 2 列 3 面板 + 1 状态条（市场温度合并风险雷达、龙头候选、运行状态）。质量评分卡和过滤有效性移至回测页；数据健康压缩为状态条中的一个状态点；验收摘要移至运行结果页。  
**后果**：驾驶舱信息密度大幅降低，30 秒内可完成决策扫描。代价是策略开发者在交易日调试策略时需要多点击一次进入回测页——但这个场景本身就是低频的。

### ADR-005：候选解释页用可展开行替代 master-detail

**状态**：已决定  
**背景**：原方案候选解释页采用 master-detail（左列表右详情），但短线交易者需要同时对比 2-3 只候选的买点和风险，master-detail 一次只能查看一只。  
**决定**：改为可展开行模式（手风琴），支持同时展开多行并排对比。  
**后果**：展开多行时页面高度可能超出可视范围，需提示用户"已展开 N 行"。桌面端体验显著优于 master-detail。

### ADR-006：导航改为频率驱动而非功能分类

**状态**：已决定  
**背景**：原方案四层导航"洞察/执行/分析/系统"按功能类别分组，导致核心操作流（驾驶舱→候选→复盘）跨越多个导航组。  
**决定**：改为按使用频率从左到右排列（驾驶舱 → 候选池 → 复盘 → 矩阵 → 配置），核心流在相邻位置，无需跨组跳转。"推荐运行"从导航中移除，改为驾驶舱主 CTA 触发。  
**后果**：导航项从 11 个减少到 5 个顶级入口，配置区承载了回测、数据健康、控制中心等多个低频功能，需确保配置区内部导航清晰。
