# 高位放量滞涨预警技能混入选股池 — 修复与验证（2026-09-18）

## 触发

用户在 `http://localhost:5174/history` 看到"最近三个月生产重建：累计单笔净收益 −33.6%"，质疑该数字。

## 一、页面数字是什么

`HistoryPage` 的「累计单笔净收益」= 当前筛选范围内**所有已成交推荐的单笔净收益之和**
（`Σ(executed_return − 0.07% 附加成本)`，见 `backend/app/services/workbench_service.py`
`_build_recommendation_history_summary`）。它不是账户复利收益率，而是"67 笔单笔收益率相加"。
按页面默认口径（近 60 天 = 2026-07-21 ~ 2026-09-18）复算，与页面一致：

| 口径 | total | 已成交 | WR | avg | Σ |
|---|---|---|---|---|---|
| 近 60 天（修复前） | 81 | 67 | 56.7% | −0.50% | **−33.61%** |
| 近 90 天（修复前） | 128 | 112 | 55.4% | −0.59% | **−66.36%** |

所以数字本身没算错——那批推荐真的亏了。真正的问题是**那批推荐里混进了一个风险预警技能**。

## 二、根因

`high-position-volume-stall-warning`（高位放量滞涨预警）是一个**命令式（imperative）风险预警技能**，
自己的 `SKILL.md` 写明"识别量在放、价不涨的顶部信号……是**该规避而非追涨**的信号"。
但它的 `manifest.json` 声明了：

```json
"meta": { "default_preset_groups": { "formal_opening": {...}, "formal_trend_core": {...} } }
```

于是它被种进了选股预设 `preset_formal_opening`，**从"风险对冲视角"变成了"选股器"**：

- 近 90 天重建的 112 笔已成交推荐里，**112 笔的 skill_breakdown 都含该技能**；
- 它**单独**触发（唯一背书技能）的 24 笔：WR 37.5%、Σ **−60.53**（占 90 天 −66.36 的 91%）；
- 它的信号分值低（例：2026-09-10 的 301626，该技能 58.6 / DSA 73.5），
  当混入多技能卡时把 blended strategy_rule 分数整体压低，再用动态降线兜底放行。

### 决定性 A/B（同一窗口 / 同一政策 / 同一权重）

`scripts/research_strategy_ablation_fast.py` 的候选集来自
`ProductionRuleReplayCandidateBuilder._selected_skills`，该函数**要求 `skill.contract`（strategy.yaml）**，
因此它天然**排除**命令式技能——也就是说它的 A 臂恰好是"不含预警技能"的生产同构重放：

| 口径（2026-06-17 ~ 2026-09-18，66 交易日） | n | WR | avg | Σ | PF | MDD |
|---|---|---|---|---|---|---|
| 研究 A 臂（**9 技能**，不含预警技能） | 137 | 60.6% | +0.849 | **+116.26** | 1.451 | −23.80 |
| 生产重建（**10 技能**，含预警技能） | 128→112 | 55.4% | −0.593 | **−66.36** | 0.742 | — |

## 三、处置

1. `backend/skills/high-position-volume-stall-warning/manifest.json`：删除
   `meta.default_preset_groups`（该技能不再声明属于任何**选股**预设；它自己的独立预设
   `0bc9fb74a9a7`「高位放量滞涨预警」保留，作为预警用途）。
2. DB `preset_skills`：删除 `preset_formal_opening:high-position-volume-stall-warning`（权重 0.3）。
   `preset_formal_opening` 现为 9 技能：炒股养家 1.0 / 陈小群 1.5 / 筹码单峰 1.0 /
   DSA 0.5 / 涨停回封 1.0 / 隔夜持股 1.0 / 主线相对强度 1.0 / 强趋势回踩 1.0 / 突破动量 1.0。
   （删掉 manifest 声明是必需的：`registry/diagnostics.require_executable` 会拦住
   "声明属于目标预设组但未进入 preset"的漂移。）
3. `backend/app/services/registry/diagnostics.py`：新增阻断级诊断
   `imperative_strategy_declares_preset_group` —— **命令式技能（无 strategy.yaml 契约）不得声明进入选股预设组**，
   否则"研究口径通过、生产重建亏损"会静默并存。回归测试见
   `backend/tests/test_registry_diagnostics.py`（含一条对真实 `skills/` 目录的仓库级不变量）。
4. `backend/scripts/research_strategy_ablation_fast.py`：新增 `--window-range START:END`，
   让研究重放能直接跑 DB 重建的实际窗口（此前只有固定 W1/W2/W3）。

## 四、验证（生产重建，重新跑 66 天，cohort `recon-v1-e50c3707…`）

重建命令：`backend/.venv/bin/python scripts/replay_sync.py --start 2026-06-17 --end 2026-09-17`（66 天 / 16.9 分钟）
，随后 `label_pending_outcomes(horizon_days=5)` 标注 151 条 outcome。

| 页面口径 | 修复前 | 修复后 |
|---|---|---|
| 近 60 天：total / 已成交 / WR / avg / **Σ** | 81 / 67 / 56.7% / −0.50% / **−33.61%** | 86 / 67 / **65.7%** / **+0.83%** / **+55.77%** |
| 近 90 天：total / 已成交 / WR / avg / **Σ** | 128 / 112 / 55.4% / −0.59% / **−66.36%** | 137 / 112 / **58.9%** / **+0.58%** / **+65.24%** |

同窗口逐笔换手（去重后 (trade_date, code)）：

- 近 60 天：交集 36/67，被替换的 31 笔从 Σ **−43.81** → Σ **+45.57**；
- 近 90 天：交集 55/112，被替换的 57 笔从 Σ **−94.89** → Σ **+36.71**。

修复后 90 天结构：PF 1.321、avgWin +4.06 / avgLoss −4.41、日均净值累计 MDD −21.49；
出场分布 `trailing_stop_hit` 32 笔 Σ+96.54、`horizon_close` 9 笔 Σ+129.29、
`stop_loss_hit` 20 笔 Σ−115.52、`stop_loss_gap` 8 笔 Σ−60.99、
`trailing_stop_gap` 43 笔 Σ+15.92。

## 五、残留

- **stop_loss_gap 仍是主要失血点**：8 笔平均 −7.62%（跳空跳过 −5.5% 止损）。
  需要的是"入场侧不追高"的闸门，而不是继续加止损。
- `sector-relative-strength-leader` 在修复后 90 天里 5 笔全负（Σ−24.83），
  单策略口径需要单独复核（下一步候选）。
- 页面口径仍然是"单笔收益率求和"，与账户复利不同；这只是展示口径，不是结算 bug。
