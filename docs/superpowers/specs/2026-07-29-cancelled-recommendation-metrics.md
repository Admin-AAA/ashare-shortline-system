# 取消买入统计与规则语义 Spec

日期：2026-07-29
状态：已实现

## 1. 目标

- 在买入条件从未命中时被系统判定“取消买入”的推荐，不进入交易成功率、失败率和实际交易收益。
- 取消推荐仍保留反事实观察：以首次取消时实时价格为参考，计算取消后第 1、3、5 个交易日收盘的假设净收益。
- 历史页明确区分当前买入判断、原始入场计划、原始失效计划、规则引用价位和历史买入命中事实。

## 2. 术语与关系

| 页面字段 | 语义 | 时间口径 |
|---|---|---|
| 当前买入判断条件 | 实时 K 重跑原策略后，本次能否入场的具体条件 | 当前实时判断 |
| 原始入场计划 | 推荐生成时保存的 `entry_rule` | 推荐生成时 |
| 原始失效条件 | 推荐生成时保存的 `invalid_rule`，表示逻辑作废或退出条件 | 推荐生成时 |
| 规则引用价位 | 入场或失效规则引用的支撑、平台、止损等价格锚点 | 推荐生成时快照 |
| 曾命中买入条件 | 有效确认窗口内至少一次返回 `buy` | 历史事实，不代表成交 |

“当前买入判断条件”属于入场判断，不是失效条件。原始失效条件独立展示。

## 3. 取消事实

`recommendation_execution_states` 增加以下单调事实：

- `cancelled_before_entry`：首次 `cancel` 发生时尚未出现过 `buy`。
- `first_cancelled_at`：首次买入前取消时间，只写一次。
- `first_cancelled_price`：首次买入前取消时实时价格，只写一次。
- `first_cancel_reason`：首次买入前取消原因，只写一次。

规则：

- `cancelled_before_entry` 只允许 `false -> true`。
- 已经 `ever_buy_confirmed=true` 后出现的 cancel 不属于“买入前取消”，而是持仓侧失效/退出信息。
- `not_ready / error / expired / cache hit` 不产生取消事实。
- V027 对已有 V026 状态做安全回填：`latest=cancel && ever_buy=false` 的记录按最后一次取消信息初始化。

## 4. 交易统计口径

- `cancelled_before_entry=true && ever_buy_confirmed=false` 时，Outcome 投影为未执行：
  - `entry_triggered=false`
  - `executed_return=0`
  - 不进入 success / failed 分母
  - 不进入实际交易收益
- 原 Outcome 模拟仍可用于内部静态行情指标，但不能冒充实际执行收益。
- Outcome 的自动结算和重算都必须应用同一执行政策，防止重算后重新进入胜负统计。
- 已经命中过 buy 的推荐继续按现有交易结算口径统计。

## 5. 取消后观察收益

参考价：`first_cancelled_price`。

观察点：取消日期之后第 1、3、5 个真实交易日收盘价，不使用取消当日最高/最低，避免把取消前行情混入反事实。

公式：

```text
取消后观察净收益 = (观察日收盘价 / 首次取消价 - 1) × 100 - 双边交易成本
```

这是“如果忽略取消并按取消价买入”的反事实观察，不是实际收益。

历史汇总新增：

- 取消票数
- 各观察窗已有样本数
- 1/3/5 日平均取消后观察净收益
- 5 日避免亏损数与比例（收益 <= 0）
- 5 日错失上涨数与比例（收益 > 0）

数据不足时返回 `null / pending`，不补零。

## 6. 前端

- “判断条件”改为“当前买入判断条件”。
- “入场”改为“原始入场计划”。
- “失效”改为“原始失效条件”。
- “价位”改为“规则引用价位”。
- 取消票展示“未计入交易胜负”。
- 有数据时展示“取消后 1/3/5 日观察净收益”，并明确标注“假设观察，非实际收益”。
- 汇总区增加取消票数、5 日避免亏损率和 5 日平均观察收益；不混入现有胜率和平均交易收益。

## 7. 深模块与 interface

新增执行结果政策模块，对调用方只暴露两个 interface：

1. `apply_execution_outcome_policy(simulation, execution_state)`：把原始模拟投影为可计入交易统计的 Outcome。
2. `build_cancel_observations(db, recommendations, execution_states)`：批量生成取消后 1/3/5 日反事实收益。

Outcome 自动结算、重算、历史行和历史汇总复用这两个 interface，不在各调用方复制取消判断。

## 8. 验收

- cancel 发生前没有 buy：Outcome 不执行，不进胜负和交易收益。
- buy 后 cancel：仍保留已执行交易统计。
- 重算 Outcome 不会让已取消票重新进入 success / failed。
- 取消后不足 1/3/5 日时对应收益为空。
- 取消后收益按首次取消价和后续交易日收盘计算，并扣统一成本。
- 历史接口和页面同时返回/展示逐票观察收益与独立汇总。
- 页面字段名称能够直接说明判断条件属于入场侧。
