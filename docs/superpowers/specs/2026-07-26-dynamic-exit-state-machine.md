# 动态退出状态机 MVP Spec

## 目标

为生产推荐结果模拟增加一套严格按交易日推进的动态退出候选实现，解决当前退出逻辑先扫描整个持有窗口、再决定是否使用移动止盈所带来的未来信息问题。

MVP 只验证一件事：使用截至上一交易日收盘已经确定的信息，更新下一交易日生效的移动保护价，是否优于无移动止盈的因果基线。

## 当前问题

权威实现位于 `backend/app/services/outcome_simulation.py`。

当前 `_resolve_exit`：

1. 先扫描完整持有窗口寻找固定止盈/止损。
2. 只要未来任意时点走到固定止盈，就完全不执行更早可能出现的移动止盈。
3. 如果没有固定止盈，再进行第二轮移动止盈扫描。
4. 入场日因 T+1 不允许卖出，同时也没有用入场日收盘信息更新次日保护价。

这不是严格可执行的单路径交易过程。

## 实施范围

### 1. 新增单路径因果退出函数

在 `backend/app/services/outcome_simulation.py` 中新增纯函数，例如：

```python
def _resolve_exit_causal(
    holding_bars,
    stop_loss_price,
    take_profit_price,
    *,
    code="",
    entry_price=0.0,
    dynamic_trailing=True,
):
    ...
```

要求：

- `holding_bars[0]` 是入场日，当天禁止退出。
- 只允许从前向后扫描一次，退出后立即返回。
- 每个交易日使用的止损、止盈和移动保护价，必须在该日开盘前已经确定。
- 禁止使用未来 bar 决定今天是否退出。
- 不修改现有 `_resolve_exit` 的默认生产调用，直到历史反事实验收通过。

### 2. 状态定义

函数内部维护以下最小状态：

```text
hard_stop             初始固定止损，持仓期间不得下调
take_profit           固定止盈价
trailing_active       移动保护是否已经激活
observed_high_return  截至上一交易日收盘已知的最高浮盈
next_trailing_stop    下一交易日生效的移动保护价
```

参数继续使用现有值：

- 移动保护激活：浮盈达到 `2.0%`
- 峰值回撤：`0.8%`
- 固定止损、固定止盈、滑点和跳空止损上限保持现有口径

### 3. 入场日收盘初始化

入场日不能卖出，但其收盘价可以用于生成次日计划。

- 只使用入场日 `close`，不要使用入场日 `high`。
- 原因：目标价可能在盘中才成交，日 K 无法判断最高价发生在入场之前还是之后。
- 若入场日收盘浮盈达到 `2.0%`，从下一交易日开始激活移动保护。
- 次日移动保护价：

```text
entry_price * (1 + (entry_close_return - 0.8) / 100)
```

- 保护价不得低于 `hard_stop`，也不得低于上一版移动保护价。

### 4. 每个可卖交易日的判断顺序

对 `holding_bars[1:]` 逐日处理：

1. 若当日不可卖（一字跌停或无流动性），跳过退出判断。
2. 若开盘价不高于固定止损，执行现有 `stop_loss_gap` 逻辑。
3. 若已激活移动保护且开盘价不高于移动保护价，按开盘价退出，原因记为 `trailing_stop_gap`。
4. 若开盘价不低于固定止盈，按开盘价退出，原因记为 `take_profit_gap`。
5. 若同一根日 K 同时触及固定止损和固定止盈，保守按固定止损退出。
6. 若最低价触及固定止损，按固定止损退出。
7. 若已经存在前一日确定的移动保护价，且最低价触及该价格，按移动保护价退出。
8. 若最高价触及固定止盈，按固定止盈价退出。
9. 当日未退出，收盘后才能用当日 `high` 更新最高浮盈和下一交易日移动保护价。
10. 持有窗口结束仍未退出，按最后一日收盘价退出。

重要：当日新形成的最高价只能更新下一交易日的移动保护价，不得反过来触发当日退出。日 K 无法证明当日 high 和 low 的先后顺序。

### 5. 退出原因展示

为 `_build_outcome_reason` 增加：

```text
trailing_stop_hit -> 盘中触发移动保护
trailing_stop_gap -> 开盘跳空触发移动保护
```

前端已经支持 `trailing_stop_gap`，无需重复增加同名映射。

## 历史反事实验证

新增只读脚本：

```text
backend/scripts/verify_dynamic_exit_policy.py
```

脚本必须：

- 使用本地数据库已有的正式 `success/failed` 样本。
- 不写数据库。
- 对同一批推荐分别运行：
  - `fixed_causal`：单路径固定止损/止盈，不启用移动保护。
  - `dynamic_causal`：单路径固定止损/止盈，加本 Spec 的动态移动保护。
- 扣除现有统一交易成本。
- 输出全样本、时间前半段、时间后半段三组结果。
- 输出样本数、胜率、平均净收益、盈亏比、最大单笔亏损、退出原因分布。

动态策略进入生产调用的门槛：

- 平均净收益不低于 `fixed_causal`。
- 盈亏比不低于 `fixed_causal`。
- 胜率下降不超过 2 个百分点。
- 最大单笔亏损不得恶化超过 0.3 个百分点。
- 时间前半段和后半段不能出现一段显著改善、另一段明显崩坏。

若未通过门槛，保留实验函数和报告，但不要替换生产 `_resolve_exit`。

## 必须新增的测试

在 `backend/tests/test_outcome_simulation.py` 覆盖：

1. 入场日触及止盈或止损仍不退出。
2. 入场日最高价超过 2%，但收盘浮盈不足 2%，次日不激活移动保护。
3. 入场日收盘浮盈超过 2%，次日移动保护生效。
4. 当日冲高激活后又回落，不允许使用当日新保护价退出；保护价只能下一日生效。
5. 前一日已生成保护价，次日盘中触及时正确退出。
6. 次日跳空跌穿移动保护价时按开盘价退出，并标记 `trailing_stop_gap`。
7. 同日固定止损与固定止盈都触发时，固定止损优先。
8. 止损价和移动保护价在持仓期间只能上移，不能下调。
9. 一字跌停不可卖时继续递延。
10. `dynamic_trailing=False` 时得到严格单路径的固定止盈止损结果。

## 非目标

本轮不要实现：

- ATR 动态止损。当前历史样本的 ATR 字段没有有效覆盖。
- 根据 MA5、第二日跌幅直接全仓卖出。本地反事实未优于当前基线。
- 分批止盈或多仓位撮合。
- 主线、龙头、情绪周期动态退出。
- 分钟级 high/low 时序推断。当前 `minute_kbars` 没有可用历史数据。
- 统一 `stock_backtest_service.py` 和通用 backtest 引擎。
- 修改推荐卡片上的初始止盈止损公式。
