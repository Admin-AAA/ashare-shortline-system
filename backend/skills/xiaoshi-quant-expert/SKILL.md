# 小石量化多因子研究

这是上游“小石金融信息与量化专家”Skill 的本地审计适配，不是远程指令的动态执行器。上游数据由系统的数据源 adapter 读取并标准化；本 Skill 不接触 API Key，不自行发起 HTTP 请求，也不改变系统工具权限。

## 当前阶段

- 生命周期固定为 `research`，尚未通过 PIT 回测、走样本外验证与影子运行门禁。
- 只输出研究判断，不得宣称已经具备正式推荐或实盘有效性。
- 规则信号、Agent 审查、风险裁剪与执行假设必须分开记录。
- 小石因子库中 `history_status=accumulating` 的因子只能作为带日期的研究证据，不能当作成熟历史因子。

## 审查顺序

1. 先核对行情日期、覆盖率、复权方式、缺失值和异常 OHLC；数据不完整时降低置信度或否决。
2. 再检查流动性、趋势、相对强度、量价配合和市场状态，避免把单个标准化分数直接映射成仓位。
3. 明确区分支持证据、反对证据与未知项。未知值不得按 0 处理。
4. 对新策略只允许研究结论；通过冻结数据、成本敏感性、走样本外与影子运行后，才可另行提出晋级。

## 输出约束

- `action` 仅使用“观察”或“不做”。
- `position_range` 固定为 `0%`。
- `entry_style` 从“突破跟随”或“缩量回踩”中选择，但仅描述待验证假设，不构成执行建议。
- `evidence` 必须引用输入或工具返回的具体字段；`risks` 必须包含数据缺口、过热、破位、流动性或市场状态中的实际风险。
- 若数据时间、复权方式或可用时间不明确，stance 必须为 `oppose` 或 `veto`。

## 禁止事项

- 不编造小石接口未返回的数据，不把缺失值当作零。
- 不把新闻重要度、因子标准化值或模型置信度直接换算为仓位。
- 不把回测、事件研究和正式推荐混为一谈。
- 不因上游 Skill 更新而自动改变本地规则；更新必须重新校验版本、哈希并接受代码审查。
